# Асимптотика и память
> Как оценивать рост времени и дополнительной памяти при увеличении входа.

## Порядок роста

Зафиксируйте размер входа и операцию, которую считаете. O(g(n)) ограничивает рост сверху с точностью до константы, Ω(g(n)) — снизу, Θ(g(n)) — с обеих сторон. Худший, средний и лучший случаи описывают разные функции стоимости. Оценка памяти учитывает выделенные структуры и стек вызовов. Отдельно оговаривайте, входит ли во вспомогательную память массив результата.

| Пример | Время | Дополнительная память |
| --- | --- | --- |
| Сумма массива | Θ(n) | Θ(1) |
| Двоичный поиск в отсортированном массиве | O(log n) | O(1) в цикле |
| Просмотр всех пар | Θ(n²) | Θ(1), если пары не сохраняются |
| Сортировка слиянием | Θ(n log n) | O(n) для массива |

## Амортизация

Когда вектор увеличивает ёмкость в постоянное число раз, отдельная вставка может копировать или перемещать все элементы. Стоимость последовательности из n добавлений остаётся O(n) благодаря геометрической сумме. Амортизированная оценка не предполагает случайный вход.

# Сортировки
> Вставки, слияние, quicksort, подсчёт и поразрядная сортировка.

## Инварианты и выбор метода

Устойчивая сортировка сохраняет относительный порядок записей с одинаковым ключом. Например, после сортировки по баллам участники с равным баллом могут остаться в порядке регистрации.

| Метод | Время | Память и условия |
| --- | --- | --- |
| Вставки | Θ(n) на отсортированном, Θ(n²) в худшем случае | O(1). Устойчивы, если сдвигать только строго большие ключи |
| Слияние | Θ(n log n) | O(n) для массива. При равенстве берём элемент слева для устойчивости |
| Быстрая сортировка | Ожидаемо O(n log n) со случайным pivot, в худшем случае O(n²) | Обычно неустойчива. При большом числе дублей помогает трёхчастное разбиение |
| Подсчёт | Θ(n + k) | k — размер диапазона. Устойчивая версия с префиксными суммами использует O(n + k) памяти |
| LSD radix sort | Θ(d(n + k)) | d разрядов, k значений разряда. Каждый проход должен быть устойчивым |

Для вставок отсортирован префикс. Слияние объединяет два отсортированных диапазона. Quicksort разбивает диапазон относительно опорного элемента и рекурсивно обрабатывает части. Точное положение pivot после разбиения зависит от выбранной схемы.

## Вставки на C++

```cpp run
#include <cassert>
#include <vector>

void InsertionSort(std::vector<int>& a) {
    for (std::size_t i = 1; i < a.size(); ++i) {
        int value = a[i];
        std::size_t j = i;
        while (j > 0 && a[j - 1] > value) {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = value;
    }
}

int main() {
    std::vector<int> a{5, 2, 4, 2, 1};
    InsertionSort(a);
    assert((a == std::vector<int>{1, 2, 2, 4, 5}));
}
```

# Стек, очередь и списки
> LIFO, FIFO, доступ по индексу и операции с узлами.

## Абстрактные типы данных

Стек извлекает последний добавленный элемент (LIFO). Очередь извлекает самый ранний оставшийся элемент (FIFO). Стек подходит для проверки скобок, очередь — для BFS. Перед `top()`, `front()` или `pop()` проверяйте непустоту контейнера.

!demo linear

## Реализации

| Структура | Операции |
| --- | --- |
| Односвязный список | У узла есть next. Вставка после известного узла и удаление его следующего — O(1) |
| Двусвязный список | У узла есть prev и next. Удаление известного узла — O(1), поиск по индексу — O(n) |
| Циклический список | Хвост связан с началом. Для обхода хранят стартовый узел или число шагов |
| Стек на списке | Вставка и снятие головы — O(1) |
| Очередь на списке | Вставка в хвост, снятие головы — O(1) при хранении обоих концов |

Кольцевой буфер реализует очередь на массиве: индекс следующей позиции считается по модулю ёмкости. Счётчик размера позволяет различать пустое и заполненное состояния. Связный список хранит указатели на узлы и обычно хуже использует кеш, а массив даёт O(1) доступ по индексу.

## Куча в массиве

Двоичная куча — полное двоичное дерево. В min-heap ключ родителя не больше ключей детей. Для индекса i при нумерации с нуля дети находятся в 2i+1 и 2i+2. Корень даёт минимум за O(1). Вставка добавляет элемент в конец и поднимает его. Извлечение корня переносит на его место последний элемент и опускает его. Обе операции стоят O(log n).

!demo heap

## Построение за O(n)

Запускайте просеивание вниз от последнего внутреннего узла к корню. Большинство узлов находятся близко к листьям, поэтому суммарная работа линейна. При heapsort на max-heap последовательно меняйте корень с концом активной части, уменьшайте кучу и восстанавливайте её свойство. Получается O(n log n) времени и O(1) дополнительной памяти при итеративном просеивании.

## Приоритетная очередь

`std::priority_queue<int>` по умолчанию отдаёт максимум. При изменении известного ключа подъём или спуск зависит от того, в какую сторону изменился приоритет. Для произвольного обновления эффективной куче нужна карта «элемент → индекс». В Дейкстре можно добавлять новую пару «расстояние, вершина» и отбрасывать устаревшие записи при извлечении.

@@ bst
# Двоичное дерево поиска
> Поиск, вставка, удаление и обходы BST.

## Порядок ключей

При уникальных ключах все ключи левого поддерева меньше ключа узла, а правого — больше. Поиск и вставка сравнивают ключ с текущим и спускаются в одну ветвь. Операции стоят O(h), где h — высота. Несбалансированное дерево может выродиться до h = n−1.

## Удаление

- Лист можно отсоединить.
- Узел с одним ребёнком заменяется ребёнком.
- У узла с двумя детьми можно взять наименьший ключ правого поддерева, перенести его в удаляемый узел и удалить прежний узел этого ключа.

Обход inorder (лево, корень, право) выдаёт отсортированные ключи. Preorder посещает корень первым, postorder — последним. Preorder восстанавливает BST с уникальными ключами благодаря его инварианту. Для произвольного бинарного дерева нужны дополнительные данные, например отметки пустых детей.

## От рекурсии к таблице

Начните с точного смысла состояния. Например, dp[i] — минимальное число монет для суммы i при неограниченном количестве монет каждого номинала. Для положительных номиналов c переход использует только меньшие суммы: dp[i] = min(dp[i−c] + 1) по всем допустимым c. База dp[0] = 0, недостижимые суммы имеют стоимость ∞.

!demo dp

Вычисляйте суммы по возрастанию. При n целевой сумме и k номиналах время O(nk), память O(n). Для восстановления решения храните монету, улучшившую dp[i]. Мемоизация вычисляет нужные состояния по запросу, табуляция заполняет их в заранее выбранном порядке.

## Кодирование без потерь

Хаффман строит двоичное дерево снизу вверх: объединяет два узла с минимальными частотами, пока не останется корень. Путь от корня задаёт код символа. Ни один код листа не является префиксом другого, поэтому поток можно разбирать однозначно. Для k символов построение дерева через кучу требует O(k log k).

При частотах A=5, B=2, C=1, D=1 возможен код A→1, B→00, C→010, D→011. Для декодирования нужно знать дерево или эквивалентное описание кодов.

Арифметическое кодирование начинает с интервала [0, 1), а каждый символ выбирает пропорциональный вероятности подынтервал. Декодер использует ту же модель и длину сообщения или символ конца. Практические реализации используют конечную точность и нормализацию. Сжатие с потерями допускает отклонение от исходного сигнала, например при кодировании звука.

## Код Хэмминга

Контрольные биты позволяют найти позицию одиночной ошибки по синдрому. Обычный код Хэмминга исправляет одну ошибку. Для одновременного исправления одной и надёжного обнаружения двух ошибок используют расширенный код с дополнительным битом общей чётности.
