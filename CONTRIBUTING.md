# Как предложить исправление

Можно исправить опечатку, неточность в объяснении, пример C++, схему, ссылку или ошибку в работе сайта. Для отправки issue или pull request нужен аккаунт GitHub.

## Сообщить об ошибке

Нажмите «Сообщить об ошибке» внизу страницы конспекта или [откройте форму на GitHub](https://github.com/linuxen/ITMO-IS-y29-cpp-algorithms-notes-1sem/issues/new?template=mistake.yml). Ссылка с сайта подставляет адрес текущей страницы.

Укажите тему, фрагмент с ошибкой и предложенное исправление. Если есть подходящий источник или скриншот, приложите его. Для других вопросов и предложений можно [создать обычный issue](https://github.com/linuxen/ITMO-IS-y29-cpp-algorithms-notes-1sem/issues/new).

## Отправить pull request

1. Откройте нужную главу и нажмите «Предложить правку» внизу страницы. Откроется исходный Markdown-файл на GitHub.
2. Если GitHub предложит создать fork, нажмите **Fork this repository**. Так создаётся ваша копия репозитория.
3. Внесите исправление в нужную тему. Один файл может содержать несколько глав. Начало главы обозначено строкой `@@ идентификатор`, ниже находится её заголовок.
4. Сохраните изменение через **Commit changes** или **Propose changes**. Откройте **Create pull request** и выберите `linuxen/ITMO-IS-y29-cpp-algorithms-notes-1sem`, ветку `main` как получателя.
5. В описании PR поясните, что было неверно, что исправлено и как проверить результат. Если исправляется issue, добавьте `Closes #номер`.

Для правки через браузер можно отправить изменение исходного Markdown. Сопровождающий пересоберёт сайт перед публикацией. При работе с локальной копией включите в PR также результат сборки из `docs/`.

## Исправление досок

Кнопка «Предложить правку» на доске открывает эту инструкцию. Схемы первого семестра находятся в `assets/media/algo1-*.svg`, второго — в `assets/media/algo2-*.svg`. Идентификатор темы совпадает с ключом в `content/boards.json` и строкой `@@` в соответствующем Markdown-файле.

Если исправление сделано в Excalidraw, приложите изменённую схему или её экспорт к PR либо issue и укажите тему. При изменении размеров изображения обновите его ширину и высоту в `content/boards.json`. Проверьте, как схема отображается в главе и на общей доске.

## Локальная сборка

Из корня вашей копии репозитория выполните команды.

```sh
python3 -m pip install -r requirements-build.txt
python3 build.py
python3 -m http.server 8000 --directory docs
```

Откройте [локальный сайт](http://localhost:8000/) и проверьте изменённую страницу. Для правок в коде укажите в описании PR, как проверялся пример. Для правок оформления полезен скриншот.

Материалы написаны для студентов. Сохраняйте смысл исходных заметок, формулируйте объяснения для общей аудитории и добавляйте обоснование технических исправлений.
